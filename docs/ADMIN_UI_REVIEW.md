# Admin UI review

Дата ревью: 2026-09-14.

## Что было

Админка функционально насыщенная, но весь frontend собран в одном `admin/index.html` (~140 KB): CSS, HTML и JavaScript живут рядом. Это быстро для прототипа, но визуальные и accessibility-правки становятся рискованными, потому что любое изменение затрагивает большой монолит.

Основные проблемы, найденные в ревью:

- 13 пунктов навигации идут одним списком без смысловых групп;
- mobile layout просто сжимает sidebar до 60 px и оставляет широкие таблицы;
- таблицы требуют горизонтального скролла и плохо читаются на телефоне;
- текущий аккаунт/режим данных не виден рядом с заголовком страницы;
- mixed RU/EN empty states (`No applications`, `Account`, и т.п.);
- `div`-навигация не была полноценной keyboard navigation;
- модалка и toast-уведомления почти не имели ARIA-семантики;
- focus state у интерактивных элементов был слабым/неполным;
- внешняя зависимость от CDN `animate.css` не нужна локальной админке;
- анимации не учитывали `prefers-reduced-motion`;
- визуальная иерархия карточек, таблиц, форм и toolbar была слишком одинаковой.

## Что изменено

Введён отдельный presentation shell без переписывания бизнес-логики старой админки:

- `admin/ui_shell.py` — чистая инъекция локальных CSS/JS в legacy HTML;
- `admin/ui_app.py` — использует тот же FastAPI backend/middleware/API, заменяя только root UI shell;
- `admin/ui.css` — visual system, mobile drawer, responsive tables, focus states, reduced-motion;
- `admin/ui.js` — nav grouping, account/scope context, keyboard navigation, ARIA, responsive table labels;
- `admin.bat` и Docker entrypoint запускают `admin.ui_app:app`.

### UX-изменения

Навигация разделена на четыре блока: «Обзор», «Данные», «Автоматизация», «Система». На мобильном sidebar стал выезжающим drawer вместо постоянной узкой полосы.

В topbar отображается контекст данных: конкретный аккаунт или режим агрегированных снимков. У каждой страницы появился короткий subtitle, чтобы было понятнее, что именно пользователь сейчас видит.

Таблицы на узких экранах превращаются в карточки с подписями колонок. Это убирает обязательный горизонтальный скролл для основных сценариев.

Добавлены keyboard navigation для sidebar, `Esc` для закрытия overlays, `Ctrl/Cmd+K` и `/` для фокуса на поиске, более явные focus states и ARIA для модалки/toasts.

## Что сознательно не переписывалось

Legacy `admin/index.html` пока остаётся источником markup и client-side business logic. Полный перенос в компонентный frontend — отдельная задача и сейчас создавал бы намного больший regression risk, чем визуальный shell.

Следующий логичный этап, если админка продолжит расти: вынести страницы из inline JS в модули и разнести хотя бы на `api.js`, `navigation.js`, `pages/*`, `components/*`. Это не требуется для текущего визуального улучшения.
